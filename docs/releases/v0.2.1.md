# Portico 0.2.1

A maintenance release. Portico behaves as in
[0.2.0](https://github.com/marco-fabbri/portico/blob/v0.2.1/docs/releases/v0.2.0.md),
whose requirements and known limits still apply, with one change of
default.

## What changed

- **The default tenant address pool is `10.128.0.0/16`.** 0.2.0's
  default, `10.100.0.0/16`, is one of the subnets Prism Central's
  microservices use inside Prism Central (`192.168.5.0/24`,
  `10.100.0.0/16`, `10.200.32.0/24`, Prism Central Guide pc.7.6), which
  Nutanix asks to keep clear of any active subnet. On NTNX-01 the Prism
  Central VM's pod network is `10.100.0.0/24`, the first tenant's `/24`
  under the old default. The tenants' subnets sit behind their VPC's
  NAT, so 0.2.0's networks work, but the overlap goes against the
  guidance and breaks any model without NAT (ADR 0009).
- **The install guide names the three reserved subnets** as ranges the
  pool must avoid, and its routed-prefix example is a documentation
  block, `198.51.100.0/24`: the routed prefix is not a VLAN, it exists
  only behind the transit VPC.

## Upgrading from 0.2.0

A stored pool is kept: an appliance installed with 0.2.0 keeps
`10.100.0.0/16`. While no ready network is built, change it on the setup
page's Tenants card; Portico moves the tenants' `/24`s into the new pool
(ADR 0008). Once a network is built the pool is fixed.

An appliance upgraded from 0.1.x straight to 0.2.1 takes the new default.

## Measured on

As 0.2.0 (write-up 35); the default change is covered by the unit tests
of `internal/settings` and `internal/tenant`.
