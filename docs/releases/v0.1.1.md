# Portico 0.1.1

A maintenance release of the appliance image and of the build. Portico
itself behaves as in [0.1.0](https://github.com/marco-fabbri/portico/blob/v0.1.1/docs/releases/v0.1.0.md),
whose requirements and known limits still apply.

## What changed

- **The first boot no longer waits a minute for the network.** At the
  first boot NetworkManager started before cloud-init wrote the
  interface's profile, made a DHCP profile of its own ("Wired connection
  1") and waited 45 s for a lease; `network-online.target` came 60 s
  late and every service after it with it (write-up 30). The image now
  turns those automatic profiles off (`no-auto-default=*`), and the boot
  test checks it.
  An appliance whose network is not given through cloud-init therefore
  has no address until the console's *Network* step sets one, as the
  install guide already says; on a network with DHCP it no longer takes
  an address by itself.
- **The build runs on Node.js 24.** Every GitHub action of the CI and of
  the release is pinned, by commit, on its first major that runs on
  Node 24, which GitHub requires after retiring Node 20: checkout 5.1.0,
  setup-go 6.5.0, upload-artifact 6.0.0, download-artifact 7.0.0,
  setup-opentofu 2.0.2, action-gh-release 3.0.3 (setup-packer 3.4.0
  already did).

## Assets

| File | What it is |
|---|---|
| `portico-0.1.1.qcow2` | the appliance image, for the Prism Central image service |
| `portico-0.1.1-oscap.html` | the OpenSCAP report of that image |
| `portico-0.1.1-linux-amd64.tar.gz` | the static binary |
| `install-0.1.1.tar.gz` | the installer and its files, for an upgrade or a host of your own |

Each file has a `.sha256` beside it. Download both into one directory
and run `sha256sum -c <file>.sha256` there.

## Upgrading from 0.1.0

A running appliance does not need 0.1.1: the change applies to the
first boot of a new image. To upgrade anyway, take a snapshot of the VM
in Prism Central, unpack `install-0.1.1.tar.gz` on the appliance and run
`bash deploy/install.sh --release 0.1.1` as root. The installer backs up
the store and the master key, replaces the binary and its files and
starts again; open sessions end.
