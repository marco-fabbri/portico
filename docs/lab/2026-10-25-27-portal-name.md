# 27 — The portal name on the appliance (Milestone 5, Task 14)

## Question

Milestone 5 renamed `public.prism_host` to `public.portal_host` (PR #36)
and the backlog asked for the lab to take the new names as the
acceptance: `msp.portico.test` for the portal and `id.portico.test` for
the identity provider, in place of `prism.lab.portico.test` and
`id.lab.portico.test`. The public names cannot change after setup (the
bootstraps write them into Keycloak and into each site's identity
provider), so the acceptance is a teardown with the product's own
removal flow and a fresh setup on the new names, which is also the
rehearsal of the install guide of Milestone 6.

## Measured on

- Prism Central: pc.7.6.0.6 on both sites (`AZ-IT-MI1`, NTNX-01
  10.23.210.175; `AZ-US-NYC1`, 10.23.210.185)
- Portico: appliance `portico-appliance` (10.23.210.191), upgraded in
  place from `dev-fc5382a` to `dev-1d6ac38` (main after the five
  Milestone 5 pull requests) at the start of the run
- Date: 2026-10-25, 00:58–01:35 CEST
- By: Claude, through the admin API and the lab scripts; the browser
  check is Marco's

## Method

Environment of write-up 22 (`PORTICO_SECRETS=~/portico-secrets-appliance`,
`LAB_VM_IP=10.23.210.191`, `LAB_SSH_USER=admin`, `LAB_REALM=portico`,
`LAB_SAML_IDP=portico-keycloak`, `LAB_PASSTHROUGH=loopback`) plus
`LAB_PRISM_HOST=msp.portico.test LAB_ID_HOST=id.portico.test` (now the
defaults of `lab/env.sh`). Passwords from the secrets files only, in
JSON bodies built with `jq --rawfile` in a private temp dir.

1. `lab/portico/upgrade-appliance.sh` (backup
   `/var/lib/portico/backup-dev-fc5382a-20261024-230011/`).
2. Teardown through the product: `DELETE /api/v1/tenants/acme/sites/{site}`
   for both sites, `DELETE /api/v1/tenants/acme`, `DELETE /api/v1/sites/{id}`
   with each Prism Central administrator's credentials (NYC1's from
   `~/portico-secrets/nyc1-pw`).
3. Keycloak realm `portico` deleted (`lab/saml/kc.sh DELETE /portico`),
   Portico stopped, store moved to
   `/var/lib/portico/portico.db.pre-portal-name-20261024-231306`
   (master key kept), new lab certificate (self-signed, SANs
   `msp.portico.test` and `id.portico.test`, `~/portico-secrets-appliance/lab-ca.*`,
   the old pair renamed `lab-ca-old-names.*`) installed as the public
   and the internal pair, Portico started: setup mode. Break-glass
   password set from the file (`portico admin set-password` on stdin).
4. `lab/portico/bootstrap-acceptance.sh`: hosts, Keycloak bootstrap,
   tenants card, branding; its site step is from Milestone 2e and fails
   now (see Result 5). Sites added with the Part C one-step path:
   `POST /api/v1/sites/inspect`, then `POST /api/v1/sites` with
   `tls_pin`, `service_account` and `admin` credentials, for both sites.
   Marco's branding put back from the backup taken before the teardown.
   `POST /api/v1/settings/apply`.
5. `POST /api/v1/tenants` (acme on both sites),
   `GET /api/v1/tenants/acme/visibility`,
   `lab/sites/tenant-login.sh --ensure-probe acme`, then
   `lab/sites/tenant-login.sh acme --site az-it-mi1` and
   `--site az-us-nyc1`.

## Result

- MEASURED: the upgraded appliance read the stored document written with
  `prism_host` and answered `portal_host: prism.lab.portico.test` on
  `GET /api/v1/settings` (the legacy key, before the teardown).
- MEASURED: the disconnect of acme from `AZ-US-NYC1` took 7 s; the one
  from `AZ-IT-MI1`, sent at the same time, was refused with 409
  "operation in progress" and done 8 minutes later, when the first had
  finished (NTNX-01 slow that night; the resource group was deleted at
  the first try). The tenant delete took 10 s.
- MEASURED: each site's Remove with the administrator's credentials took
  9 s (`AZ-IT-MI1`) and 4 s (`AZ-US-NYC1`): the identity provider's one
  SAML user, the identity provider, the service account's key and the
  Keycloak SAML client deleted; "left in Prism Central: Portico's
  service account", which both Prism Centrals confirmed (account
  `portico` present, no keys).
- MEASURED: the Keycloak bootstrap on the empty realm took 76 s
  (realm, `portico-admin`, `portico`); the OIDC client's redirect URI is
  `https://msp.portico.test/.portico/callback`.
- MEASURED: `POST /api/v1/sites` with `tls_verify: false` and no pin is
  refused with 400 "a new site needs a trusted or pinned certificate"
  (Part C): `lab/portico/bootstrap-acceptance.sh` steps 3 to 5 fail on
  a current build and need the one-step path (follow-up below). The

  `service-account`, `saml-trust`, `defaults`, `live`) all ok; the
  service account was found and got a new key on each Prism Central.
  The sites are `az-it-mi1` (`Milan 1`) and `az-us-nyc1` (`New York 1`),
  entity ids `https://msp.portico.test/api/iam/authn/<id>`, trust
  `pinned`, status `available`.
- MEASURED: Apply, back in running mode after 6 s;
  `https://id.portico.test/realms/portico` 200 through the proxy.
- MEASURED: tenant acme active on both sites in 17 s; the visibility
  check ok on both with no findings.
- MEASURED: the probe user's login through `https://msp.portico.test/`
  reached `/console/` (200) on each site: Keycloak on `id.portico.test`,
  the SAML callback on `msp.portico.test/api/iam/authn/callback`,
  `NTNX_SESSION_ID` set, the jar holding `__Host-portico_session`,
  `iam-sessionid` and `NTNX_SESSION_ID`, as in write-up 20.
- Not measured here: the browser login (Marco), with the new
  certificate to trust in the browser.

## Implications for the design

None for the design. For the lab: `lab/portico/bootstrap-acceptance.sh`
is the Milestone 2e flow and its site steps predate Part C; it should
add the site with the one-step path (backlog). The old lab VM (.190)
keeps the old names; its scripts need `LAB_PRISM_HOST`/`LAB_ID_HOST` set
to them now that `lab/env.sh` defaults to the portal names.

## How to re-measure after an upgrade

```
export PORTICO_SECRETS=~/portico-secrets-appliance LAB_VM_IP=10.23.210.191 \
  LAB_SSH_USER=admin LAB_REALM=portico LAB_SAML_IDP=portico-keycloak \
  LAB_PASSTHROUGH=loopback \
  LAB_SSH_OPTS="-o UserKnownHostsFile=/dev/null -o StrictHostKeyChecking=no"
source lab/env.sh
lab/tenants/api.sh GET /api/v1/settings | jq '{portal_host, id_host, mode}'
lab/sites/tenant-login.sh acme --site az-it-mi1
lab/sites/tenant-login.sh acme --site az-us-nyc1
```
