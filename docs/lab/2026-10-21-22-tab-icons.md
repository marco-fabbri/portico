# 22 — Tab icons on the appliance

## Question

Do Portico's pages, Keycloak's login page and the admin UI show a tab
icon in Chrome and in Safari; does an MSP's own PNG, not square and under
180 px, replace Portico's arch on the tenant pages and on the login; and
does a change of icon reach a browser that already holds the old one?

## Measured on

- Prism Central: pc.7.6.0.6 (untouched: Portico does not change Prism
  Central's pages, its console keeps Nutanix's icon)
- Portico: the appliance `portico-appliance` (10.23.210.191), upgraded
  from `dev-af25247` to `dev-efe8d3d` (branch `favicon`); Keycloak
  26.3.5, login theme `keycloak.v2` with Portico's theme on top
- Browsers: Chrome 155.0.8059.85 and Safari 27.0.1 on macOS 27.0.1
- Date: 2026-10-21
- By: Claude, with the scripts below; the browser views were Marco's
  (crops of the tab strip), the requests behind them read from Portico's
  access log

## Method

- `lab/portico/upgrade-appliance.sh` (store and master key copied to
  `/var/lib/portico/backup-dev-af25247-20261021-072805/` first).
- `lab/portico/tab-icons.sh` fetches the icons on both public names and
  on the admin listener (status, type, `Cache-Control`, the images in
  the ICO, the size of the touch icon), follows a tenant login to
  Keycloak's page and compares the favicon that page links with
  Portico's. `--set PNG` stores a tab icon through
  `PUT /api/v1/settings/branding` keeping the rest of the branding;
  `--log MINUTES` lists the login pages and icon requests of the access
  log, which tells which browser load fetched an icon.
- In the browsers: the tenant login (`https://prism.lab.portico.test/`),
  a tenant login through to the console, Prism Central's Sign Out, and
  the admin console (`https://10.23.210.191:8443/`), in a normal and in a
  private window, first with the arch, then with the MSP's icon: a
  167×178 RGBA PNG mark (not in the repository).
- Keycloak's login template read from its themes jar on the appliance.

## Result

- MEASURED: `tab-icons.sh`, every line ok, with the arch and again with
  the MSP's icon: `favicon.ico` with three images (16, 32, 48 px) on
  both public names, `Cache-Control: no-cache`; the 180×180
  `apple-touch-icon`; the admin UI's own pair (`public, max-age=86400`,
  versioned by the binary), different from the tenants'; Keycloak's
  login page links `/resources/0lpw6/login/portico/img/favicon.ico`,
  served with `no-cache`, byte for byte Portico's `favicon.ico`.
- MEASURED: the arch, before the MSP's icon. Chrome and Safari: the
  admin tab shows the arch on dark grey, the tenant login the arch on
  the accent colour (`#a73422`).
- MEASURED: the MSP's PNG (167×178) was accepted, centred on a square
  and scaled (enlarged to 180 px for the touch icon); `favicon.ico`
  4040 bytes. The save answered 200 with no warning and left name,
  tagline, accent, logo and display time unchanged. Keycloak served the
  new favicon at the next request, with no restart (the theme is a
  mounted directory, write-up 13).
- MEASURED: Chrome fetched the login's favicon again on a reload and
  showed the MSP's icon.
- MEASURED: Safari, normal window. It fetched the login's favicon once,
  at its first visit (after asking for `/apple-touch-icon-precomposed.png`
  and `/apple-touch-icon.png` at the root of `id.`, which the identity
  host's policy refuses with 403), and never again by itself: after the
  change its login kept the arch through several loads, a tenant login
  and a Sign Out. On Portico's landing page, whose link carries
  `?v=<icon version>`, it fetched the new favicon at the first load.
  After Develop > Empty Caches and a reload it fetched the login's
  favicon and showed the MSP's icon.
- MEASURED: Safari, private window. It fetches no favicon at all. The
  admin console showed the dark arch from the normal window's cache (no
  request in the log); the login showed Safari's placeholder, the host's
  initial in a grey square, since the login page's address carries a
  new query at every login and the cache has nothing for it.
- MEASURED: `keycloak.v2`'s `login/template.ftl` (26.3.5) links
  `${url.resourcesPath}/img/favicon.ico`; the resources path changes with
  Keycloak's version only, and no theme property sets the link.
- NOT MEASURED: Firefox (not installed on the Mac), the touch icon on
  iOS, Windows browsers, how long Safari keeps a favicon before it
  fetches it again by itself.

## Implications for the design

- The tab icons of design 4.10 stand: every browser tested reads the
  ICO, and Portico's own pages update at once after a change.
- Known limit: Safari keeps the login page's icon until its caches are
  emptied, because Keycloak links it at a fixed address. A tenant who
  used Safari before the MSP changed its icon sees the old one on the
  login page only. Not fixed: a versioned link means overriding
  Keycloak's whole page template, which would have to follow every
  Keycloak upgrade, for an icon. Recorded in design 4.10 and
  `docs/operating.md`.
- Safari asks for `/apple-touch-icon.png` at the root of the identity
  host; the 403 stays, nothing on that host needs it.

## How to re-measure after an upgrade

```
export PORTICO_SECRETS=~/portico-secrets-appliance LAB_VM_IP=10.23.210.191 \
  LAB_SSH_USER=admin LAB_REALM=portico LAB_SAML_IDP=portico-keycloak \
  LAB_PASSTHROUGH=loopback \
  LAB_SSH_OPTS="-o UserKnownHostsFile=/dev/null -o StrictHostKeyChecking=no"
source lab/env.sh
lab/portico/upgrade-appliance.sh            # restarts Portico: tenant sessions end
lab/portico/tab-icons.sh
lab/portico/tab-icons.sh --set MARK.png     # a PNG mark, 128 to 1024 px on its longer side
# in Chrome and Safari: reload the tenant login, sign in, sign out; then
lab/portico/tab-icons.sh --log 10           # which loads fetched an icon
lab/portico/tab-icons.sh --remove           # back to the arch
```
