# 02 — Lab VM `portico-lab` on NTNX-01 via the v4 API

## Question

Not a design item: infrastructure for items 6.1, 6.2, 6.4, 6.5, 6.6. It also
measures, as a by-product, how a VM is created on pc.7.6 through the v4
API, which Milestone 2's visibility check and Milestone 3's install guide
will reuse.

## Measured on

- Prism Central: pc.7.6.0.6, cluster NTNX-01 (AOS 7.6)
- Date: 2026-10-17
- By: Claude (Marco's session), `lab/vm/create-vm.sh`

## Method

`source lab/env.sh && lab/vm/create-vm.sh`, then SSH as `lab@10.23.210.190`.
The IP was confirmed free by Marco; `ping` from the Mac got no reply.
`arping` is not possible from the Mac (it reaches VLAN 210 through a VPN
tunnel, `utun9`), and the Prism Central VM list showed no NIC with that IP.

## Result

- MEASURED: all four calls worked on their **v4.0** paths, no v3 fallback:
  `POST /api/vmm/v4.0/content/images` (UrlSource), `GET /api/clustermgmt/v4.0/config/clusters`,
  `GET /api/networking/v4.0/config/subnets`, `POST /api/vmm/v4.0/ahv/config/vms`,
  `POST .../vms/{extId}/$actions/power-on` with `If-Match`. Served
  versions: vmm `v4.r3`, networking `v4.r4`, prism tasks `v4.r4`.
- MEASURED: image download by Prism Central from dl.rockylinux.org
  (Rocky 9 GenericCloud, ~600 MB) took about 10 minutes; the task reports
  `progressPercentage`. VM creation from the image took under 2 minutes;
  boot to SSH about 1 minute. Rocky Linux release 9.8.
- MEASURED: a disk cloned from an image with `diskSizeBytes` larger than the
  image (40 GiB) is accepted in the same call and the guest sees the full
  size (`/dev/sda4` 39G).
- MEASURED: only one subnet exists on NTNX-01: `MGMT`, VLAN 0, and it is
  the one carrying `10.23.210.0/24` (the PCVM is on it). The lab VLAN has
  **no DHCP**.
- MEASURED: with cloud-init, the static network must be set in `bootcmd`.
  The first attempt put the NetworkManager profile in `write_files` and
  `nmcli` in `runcmd`: `dnf` ran before `runcmd`, had no network, and
  cloud-init ended in `status: error` with no packages installed. With the
  profile written and activated in `bootcmd`, cloud-init ends in
  `status: done` with podman 5.8.2 and nginx 1.20.1 installed.
- MEASURED: v4 `$actions` (power-on, power-off) and `DELETE` need the
  `If-Match` header with the ETag from a `GET` of the entity, or they are
  rejected. `lab/pc.sh` got `PC_HEADERS_FILE` for this.
- MEASURED: the list endpoints accept `$filter=name eq '<name>'`
  (OData style), used for idempotency.
- MEASURED: the `_internal` project accepted the VM without any
  `projectExtId` in the request (the VM landed in the Default Project).

## Implications for the design

- The appliance install guide (Milestone 3) can offer an API-driven path
  identical to `create-vm.sh`: image from URL, VM from image, cloud-init
  for first network settings. The console wizard remains the attended path.
- The Portico appliance's own cloud-init must configure the network in
  `bootcmd` for the same reason.
- Milestone 2's live visibility check can create a probe VM with the same
  calls, adding `projectExtId` of the tenant project (to be measured in
  write-up 05).

## How to re-measure after an upgrade

`lab/vm/delete-vm.sh && lab/vm/create-vm.sh`, then
`ssh lab@10.23.210.190 'sudo cloud-init status; podman --version; nginx -v'`.
