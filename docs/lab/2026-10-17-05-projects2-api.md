# 05 — Projects 2.0 API surface on pc.7.6 (design 6.3)

## Question

Which v4 calls create a project, allocate clusters and storage containers,
bind a group to a role inside the project, and delete it; what the Default
Project looks like and how Portico must leave it alone.

## Measured on

- Prism Central: pc.7.6.0.6, cluster NTNX-01
- Date: 2026-10-17
- By: Claude (Marco's session), `lab/projects/*.sh`

## Method

`lab/projects/create.sh`, `bind-group.sh`, `delete.sh` against a throwaway
project `portico-lab-tenant-b` (created, bound, deleted as `admin`), then
again as the `portico` service account with `portico-lab-tenant-c`
(write-up 07; the committed payload files come from that last cycle), and
the lab project `portico-lab-tenant-a` (kept for the SAML tests). API paths from the public
Go clients; the scope template name from the Nutanix Terraform provider's
Projects 2.0 guide (`kb/terraform/`). Isolation checked with a local user
`portico-lab-bob` bound as Project Admin of tenant A, calling the API with
Basic auth.

## Result

The tenant shape, as calls (payloads in `docs/lab/payloads/`):

| step | call | notes |
|---|---|---|
| project | `POST /api/multidomain/v4.4.b1/config/projects` `{id, name, description}` | **`id` (a slug) is required** ("missing property 'id'"); returns a task; `extId` is a UUID distinct from `id` |
| infrastructure | `POST /api/multidomain/v4.4.b1/config/resource-groups` `{name, projectExtId, placementTargets:[{clusterExtId, storageContainers:[{extId}]}]}` | Prism Central **adds `SelfServiceContainer` by itself** to the placement target (SP Central documents the same) |
| SAML group | `POST /api/iam/v4.0/authn/user-groups` `{name, groupType:"SAML", idpId}` | the group name must match the `groups` attribute Keycloak sends |
| IdP sharing | `POST /api/iam/v4.1.b3/authn/config/saml-identity-provider/{extId}/$actions/share` `{projectExtId}` with `If-Match` | singular `projectExtId`; `projectExtIds` is rejected. Required: the project only sees identity sources shared with it |
| role binding | `POST /api/iam/v4.1.b3/authz/role-memberships` `{identityExtId, identityType:"GROUP"\|"USER", idpExtId, projectExtId, roleExtId, scopeTemplateName:"ProjectsScopeTemplate", scopeTemplateNameValues:[{name:"projectExtId", value}]}` | `scopeTemplateName` is mandatory; `GET .../scope-templates` answers 403 "allowed only through mTLS", so the name cannot be discovered from the API. `Project Admin` role extId `ca386756-e45f-5555-8625-5b68ae17393b` (system defined) |
| delete | memberships `DELETE`, IdP `$actions/unshare`, resource groups `DELETE`, project `DELETE`, all with `If-Match` | project delete **fails while the IdP is shared** (`associatedEntities={"shared saml identity providers":1}`) |

- MEASURED: `_internal` (`id=default`, extId all zeros, `isDefault`,
  `isSystemDefined`) is the only project on a fresh 7.6. Snapshot before and
  after the tenant-b cycle with
  `lab/pc.sh GET /api/multidomain/v4.4.b1/config/projects | jq '.data[] | select(.name=="_internal")'`
  and `diff` of the two files with `modifiedTimestamp` removed: identical.
  `modifiedTimestamp` did change, which is expected and not caused by the
  project scripts: between the snapshots the lab VM (write-up 02) was
  created inside `_internal` and the subnet `MGMT`, owned by `_internal`,
  was shared with tenant A (below). Portico must never address `_internal`;
  the project scripts refuse any name outside `portico-lab-*`.
- MEASURED: the v3 `projects/list` returns 0 entities on 7.6 even with a
  Projects 2.0 project present. v3 is irrelevant for tenants.
- MEASURED: the authorization policy generated by a role membership is
  **not visible** in `GET /api/iam/v4.*/authz/authorization-policies` (count
  stays 5); `GET /api/iam/v4.1.b3/authz/role-membership-summaries` lists
  per-project counts (`groupsCount`, `usersCount`). The static visibility
  check of design §4.4 must read role memberships, not policies.
- MEASURED, isolation as `portico-lab-bob` (Project Admin of tenant A, Basic
  auth): projects → only tenant A; clusters and storage containers → **403**;
  VMs and subnets → empty (nothing shared with the project yet); images →
  the one image shared with all projects; SAML IdPs → the one shared with
  the project. **Users → all 7 local users and service accounts are listed.**
  Role memberships → 2 (his and the group's, both tenant A).
- MEASURED: subnet `MGMT` belongs to `_internal` with no sharing; a tenant
  VM needs the subnet shared first:
  `POST /api/networking/v4.4/config/subnets/{extId}/$actions/share`. The
  Rocky image has `isSharedWithAllProjects=true` (images uploaded by admin
  are shared globally by default).
- MEASURED (Task 8 preparation): `POST /api/networking/v4.4/config/subnets/{extId}/$actions/share`
  `{projectExtId}` with `If-Match` shares a subnet with a project (task,
  then `sharedWithProjects` lists it). A VM created by admin with
  `projectExtId` set lands in the project; `portico-lab-bob` then sees the
  VM and the shared subnet, nothing else.
- MEASURED: quotas are not part of these APIs. The Projects Guide ties
  quotas to the Policy Engine (NCM Self-Service) and the Terraform Projects
  2.0 guide has no quota resource. Quota automation is step 2 and may need
  Self-Service enabled.
- MEASURED: local user creation (`POST /api/iam/v4.0/authn/users`) enforces
  a password policy of four character classes (upper, lower, digit,
  special).

## Implications for the design

- Milestone 2's tenant provisioning is these six calls in this order, plus
  Keycloak group creation; deletion is the reverse with the IdP unshare.
  Pin `multidomain/v4.4.b1` and `iam/v4.1.b3`; read `$reserved.$fv` to
  detect a version change.
- Tenant row (design §4.4) needs: project `id` (slug) and `extId`, resource
  group extId, SAML group extId, role membership extId(s), and whether the
  IdP is shared. `scopeTemplateName` is a constant.
- The public-path policy of the proxy should deny `/api/iam/*/authn/users`
  listing for tenants (a Project Admin can enumerate all accounts).
  Candidate for the allow/deny list of write-up 08.
- Quotas: step 2, after measuring the Policy Engine.
- Naming: SP Central uses `sp-<tenant>`; Portico uses `<prefix>-<slug>` with
  a configurable prefix, default `portico`.
